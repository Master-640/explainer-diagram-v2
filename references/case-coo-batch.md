# 案例复盘：GRACO `nx.Graph → BatchedGraph`（COO）

产物：`graco_coo_batch.png`（工作区）· 完整脚本：`<workspace>/draw_coo_batch.py`

## 为什么这样构图

原问题是"两张 networkx 图怎么变成一张 COO 张量"。这里**真正的难点不是流程，而是三个容易漏的细节**：
对称化、节点偏移、batch/ptr 分组。所以版式定为：

| 区域 | 承担的问题 |
|---|---|
| ① 输入 | 两张图长什么样、节点编号会冲突 |
| ② 对称化 | 为什么无向边要写两遍（COO 语义） |
| ③ 节点偏移 | 为什么 G2 要 +4（全批共用编号） |
| ④ 拼接 | 输出字段从哪来（cat / num_nodes / ptr / batch） |
| 底部 | **把真实的 2×12 张量逐格画出来**，按来源染色 + 括号标注 |

如果只画 ①→④ 四个框，读者仍然不知道"输出长什么样"；底部张量区才是图的主体。

## 关键坐标（可直接复用）

```python
fig = 15.2 × 9.2
标题 y=8.80 / 副标题 y=8.46
四个箱:  (0.20, 4.70, 4.05, 3.50)  (4.45, 4.70, 3.55, 3.50)
         (8.20, 4.70, 2.75, 3.50)  (11.15, 4.70, 3.85, 3.50)
底部大箱: (0.20, 0.30, 14.80, 4.18)
张量网格: x0=1.35, y0=3.05(第一行) / 2.55(第二行), cw=0.80, ch=0.50
分组括号: y=2.02，标签 y=1.80
kv 行:   y=1.28
脚注两行: y=0.88 / 0.54
```

## 决策记录（值得照抄的手法）

1. **分组用颜色 + 括号**，不用文字反复说"前 8 列来自 G1"。蓝 `#EAF1F8` / 橙 `#FBEEE2` 两种格底，
   数字本身也染成对应的深色，读者扫一眼就知道边界。
2. **冲突点用红字**：「注意：G2 的编号与 G1 重复」放在 ① 内，为 ③ 的偏移做铺垫。
3. **代码片段用 mono 但只放 ASCII**：`for u, v in G.edges():` 三行放在 ②，中文说明单独一行。
4. **底部两行脚注**：一行讲"为什么还需要 batch/ptr"，一行讲"对照 CSR"。这两句是全图信息密度最高的部分。
5. **`x = None` 单独标红**：强调"组张量这一步不造特征"，防止读者误以为特征在这里。

## 踩过的坑（复现时别再踩）

| 现象 | 原因 | 修法 |
|---|---|---|
| `G□`、`N□` 方框 | `G₁ / N₁ / ⚠ / Σ / ₖ` 字形 YaHei 无 | 改 `G1 / N1 / 注意：/ sum(n_k)` |
| 整串中文消失 | `family="monospace"` + 中文同一次 `ax.text` | 拆成两次调用：中文默认字体、代码 mono |
| 「G1：n=4」压住节点 0 | 标签放在图上方而节点也在上方 | 标签移到图的右侧空白处（`2.95, 6.85`） |
| 底部标题压住 `shape` 行 | 箱高 4.05、标题基线 `y+h-0.26` 与内容只差 0.26 | 箱高加到 4.18，内容下移到 `3.86` |
| 底部留大片空白 | 网格只占 12 列中的 6 列宽 | 左侧补 kv 行与脚注，或缩窄画布 |

## 复用到自己的数据时

只要替换三处：① 的图（或改成"文件几行文本"）、底部 `rows` 的两行数字、脚注里的"为什么"。
`tensor_grid(..., group_sizes=[8, 4], group_colors=[蓝, 橙])` 直接支持任意分组。
