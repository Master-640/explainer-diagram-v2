# 11 种图型的排布配方

每种配方给出：**判定条件 → 骨架坐标 → 用哪些构件 → 必写的硬信息 → 常见错**。
画布默认 15.2 × 9.2 inch（外框：`x∈[0.2, 15.0]`，标题带 `y>8.2`，底部 `y<1.0`）。

---

## M1 数据流 / 张量布局

- 判定：输入是数据，经过若干步成为一个形状明确的张量，且"形状/索引"是重点。
- 骨架：上排 4 个箱子（`y=4.7, h=3.5`，宽 3.35–3.65），下带大框（`y=0.3, h=4.1`）放产物网格。
- 构件：`box` + `text`/`footnote` 写步骤 + `tensor_grid` 写产物 + `bracket` 标分组 + `kv_lines` 写 `batch/ptr`。
- 必写：`shape [...]`、具体索引值、分组来源（哪几列来自哪个输入）。
- 常见错：只写"一个 2×N 矩阵"；网格数字与源码不一致；分组只用文字说不用颜色。

## M2 系统架构 / 模块接线

- 判定：有分层（接入/服务/数据）、有部署边界、关心"谁调用谁"。
- 骨架：2–3 条横泳道 `lane(y=7.0/4.6/1.6, h≈1.3–1.8)`，每道 2–3 个箱子；右侧竖列放图例与约束。
- 构件：`lane` + `box` + `arrow`（同层）/`elbow`（跨层）+ `legend` + `callout` + `kv_lines`（SLO）。
- 必写：调用方向、关键约束（QPS/延迟/TTL）、旁路或异步环节要显式点出。
- 常见错：泳道标签与副标题撞车（泳道顶 ≤ 8.3）；箭头穿框；把"旁路"画成必经。

## M3 流水线（阶段 + 产物）

- 判定：每步都有落盘产物（文件/表/模型），读者关心产出物。
- 骨架：左→右 3–5 个阶段箱，箱内写"输入→输出"；下方一条产物带列文件名与行数/大小。
- 构件：`box` + `arrow` + `chip`（产物名）+ `kv_lines`。
- 必写：每个阶段的产物名与验收口径（行数、shape、通过条件）。
- 常见错：只画阶段不写产物；阶段 > 5 不拆图。

## M4 A / B 对比

- 判定：两套口径/两个版本/修复前后，要读者一眼看出差异。
- 骨架：左右等宽两箱（`x=0.4 w=6.55` / `x=7.25 w=7.55`），中间一个红箭头；下方通栏"合起来怎么说"。
- 构件：两个 `box(tint=)` + 对称 `tensor_grid` + 每侧一行加粗结论 + `callout`（反例）+ 三行 `why()`。
- 必写：两侧各自的"结论"一行；差异处用同色系不同深浅或灰化；反例要写出"为什么错"。
- 常见错：只摆两列数据不给结论；差异格不加标记；两侧坐标不对齐导致视觉错位。

## M5 时间线 / 里程碑

- 判定：排期、事件推进，每点有可验收产出。
- 骨架：一条横轴 `y≈7.0`，6 个点左右；点上方写时间，下方写里程碑名；下方 2–3 行写验收口径与红线。
- 构件：`timeline` + `text`（口径）+ 红线用 `PALETTE["red"]`。
- 必写：每个里程碑的验收口径；"之后不再改什么"这类红线。
- 常见错：点太密（> 8 个换纵向）；只写日期不写产出。

## M6 状态机 / 决策树

- 判定：有限状态 + 转移条件，或分支判定。
- 骨架：3–6 个状态节点环形或链式排布，边标签写条件；入口在左、终态在右或下。
- 构件：`node_graph(directed=True)` 或手摆 `box` + `arrow` + 边上 `text`。
- 必写：每条边的触发条件；非法转移用红虚线标注。
- 常见错：边不写条件；状态与动作混为一谈。

## M7 层次 / 分类树

- 判定：一层总、下层分；词表、模块归属、分类体系。
- 骨架：顶层一个框居中，`y≈2.9`；下一层 3–4 个框一排 `y≈1.9`；连线正交。
- 构件：`tree(cx, y, root, [children])`；多于 4 个子节点改两层。
- 必写：每层的划分依据（按什么分的）。
- 常见错：子节点 > 5 仍挤一排；连线交叉。

## M8 单点放大

- 判定：讲清"这一格/这一行/这一步内部是怎么算的"。
- 骨架：左侧小框（全景）+ 引出线 + 右侧放大框（细节），放大框内可再放网格。
- 构件：`box` + `annotate(arrowstyle="-")` + `tensor_grid`。
- 必写：放大框与全景框的对应关系（同色边框或同编号）。
- 常见错：放大后忘记标"这是全景里的哪一块"。

## M9 因果环 / 反馈回路

- 判定：正负反馈、闭环（Bjerknes、控制回路、经济循环）。
- 骨架：4–6 个变量节点绕环排布；每条边标 `+` / `−`（正负反馈）；环中心写"总效应"。
- 构件：`node_graph` + `arrow` + 边标签；正反馈蓝、负反馈红。
- 必写：每条边的符号；环的净效应（自增强 / 自抑制）。
- 常见错：符号缺失；把相关当因果（需在副标题写口径）。

## M10 带标注的图（annotated chart）

- 判定：结论来自真实曲线/柱状，需要把关键点标在图上。
- 骨架：主体是真图（`ax.plot/bar`），右上或右下留白放图例；3–5 个 `callout` 指向关键点。
- 构件：matplotlib 原生 + `annotate` 箭头 + `callout`。
- 必写：数据来源与统计口径（均值/中位、窗口、样本数）；标注阈值或拐点的具体数值。
- 常见错：标注压线；不给数据口径；装饰性标注（不携带信息的箭头）。

## M11 步骤卡（in / out / 代码 / 示例）

- 判定：要讲清"一条流水线里每一步在干什么"，且读者是**要照着核对代码**的人（自己/同组），
  不是路人。核心诉求是"这个框的输入是什么、输出是什么、我怎么验"。
- 骨架：上排 3–4 个等宽箱（`y=5.45, h=2.78, w=3.55`，间距 `x += 3.75`），
  箱内四段式；底部通栏 `box(y=0.90, h=4.35)` 放"钩子 + 产物"；最底一条 `callout` 写口径/偏差。
- 箱内四段（**顺序固定，缺一段就重画**）：
  1. 中文一句话：这一步在干什么（≤2 行，`size=9.0, color=soft`）；
  2. `in:` / `out:` 两行，写形状或值（in 蓝、out 绿，`size=8.4, mono`）；
  3. 代码 2 行，能指到源码函数的真实调用（墨色，`mono`）；
  4. 示例 1–2 行，**同一个例子贯穿所有框**（橙色，`mono`）。
- 底部通栏三段：左=控制流钩子（谁在什么时候触发学习）、中=示例的可视化（小图 before/after）、
  右=产物清单（一条转移 / 一次更新的具体字段值）。
- 必写：每一步的 in/out 形状；示例里能算对的值（如 `LCC 5 -> 3`、`r = -3/25 = -0.12`）；
  示例数值必须标「ex/示例」，与实测值（来自日志的 `46.4`、`7,000`）在颜色或措辞上分开。
- 常见错：
  - 只写代码不写 in/out——读者不知道这个框吃进去什么；
  - 每个框用不同的例子，串不起来；
  - 示例值算错（画完必须手算一遍：删掉节点后连通块还算不算得对）；
  - `mono=True` 里混中文（kit 会直接抛错，拆成两次 `text()`）；
  - 示例框和实测框混排，分不清哪个是编的。
- 模板：`scripts/demo_step_cards.py`（顶部 `STEPS` / `LEFT` / `RIGHT_KV` 三处改成你的内容即可）。

## 组合规则

- 一张画布最多 **2 张子图**（例：时间线 + 树），每张子图独立编号 ①②。
- 子图之间留 0.3 inch 以上空白，或用不同 `tint` 的 `box` 包裹。
- 同一张图里颜色语义只增不减：蓝=主对象、橙=次对象、灰=流程/背景、红=反例/红线。
